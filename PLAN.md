## What the AI service is

| Person | Owns |
| --- | --- |
| Frontend teammate | React reviewer UI at `100.117.73.55:5173`; it talks only to the backend |
| Backend teammate | FastAPI at `100.83.115.82:8000`: context, all deterministic rules (classification, eligibility, billing, consent, contact limits, canonical template rendering), drafts, review, mock delivery, audit, and the 2 tools |
| Me (AI part) | A thin FastAPI service at `100.114.163.7:8001` with **one endpoint**: `POST /internal/v1/generate` |

```
React ─► Backend ─► AI  POST /internal/v1/generate (AIRequest → AIResponse)
                    AI ─► Backend  POST /internal/v1/tools/execute
                                     1. evaluate_customer → Plan
                                     2. validate_draft    → Validation
```

**One turn of the AI service:**
1. Check the service bearer token and the `X-Delegation-Token` header, and that `customer_id` and `as_of` in the body match.
2. Call `evaluate_customer` → `Plan`. If the plan is blocked → return `blocked`, `message=null`, `model_version=not_invoked` (no Gemini call).
3. Build the Gemini instruction from the approved template + minimum facts (data kept separate from instructions); ask for structured `Message` + evidence.
4. Parse locally; at most 1 repair attempt; still bad or Gemini down → `unavailable`, `message=null`.
5. Call `validate_draft` → pass → `generated`; fail → `blocked` with that validation.
6. Budgets: 22 s total, 3 s per tool call, 15 s for Gemini, at most 2 tool calls and 2 Gemini attempts. A full timeout → `504 AI_TIMEOUT`.

The AI service does **not** re-implement business rules as the authority, store drafts, send email or expose any frontend API.

## Phases

Each phase ends with passing tests. No commits during the phases: everything is committed once on `AIpart` after all phases are done, and pushed only after you confirm. I ask you before starting each phase.

### Phase 0 — Setup & contract models
- git repo, remote, branch `AIpart` (done)
- `ai-service/` skeleton, `requirements.txt`, `.env.example`, `.gitignore`
- Pydantic models for the whole JSON Schema registry (closed objects, all fields required, nullable only where allowed)
- The registry extracted to `ai-service/contract/schema-1.0.0.json`, with tests that check the models against it and against the contract examples
- `Error` envelope for every failure, including FastAPI's 422; `X-Request-ID` echo, `X-Contract-Version: 1.0.0`, `Cache-Control: no-store`
- Service auth (`Authorization: Bearer <AI_SERVICE_TOKEN>` + `X-Delegation-Token`)
- `POST /internal/v1/generate` validates the request and returns `503 SERVICE_UNAVAILABLE` until Phase 3
- **Done when:** the server starts and the tests pass

### Phase 1 — Backend ToolClient (done)
- **No synthetic data is generated by the AI service.** The real data comes from the backend over Tailscale; tests use only the contract's own examples.
- `ToolClient` interface with exactly `evaluate_customer` and `validate_draft`
- `HttpToolClient` → `POST /internal/v1/tools/execute` with `BACKEND_TOOL_TOKEN`, the turn's delegation token and `X-Request-ID`; 3 s per call
- Responses validated against the contract; wrong tool or turn, unknown fields or non-JSON → 503
- Backend errors passed on with the same code and status but redacted; timeouts raise `ToolTimeout` for the orchestrator
- `scripts/check_backend.py`: checks the backend `/health` over Tailscale
- **Done when:** the client tests pass and the backend `/health` check passes once the backend is running

### Phase 2 — Templates, prompt & Gemini adapter (done; model `gemini-3.5-flash-lite`)
- Safe template renderer: the allowlisted placeholders only, single substitution, INR formatting
- Versioned prompt `prompt_v1`: system instruction separating data from instructions; facts passed as data only; no bill/account numbers or email addresses
- `GeminiAdapter` interface, plus the real `google-genai` implementation (low temperature, JSON schema output, model from `GEMINI_MODEL`, actual model version recorded)
- Test doubles for Gemini replies (exact, schema-invalid, unsupported claim, failure) built from the contract's own example text, not new data
- **Done when:** tests with the mock pass, without needing an API key or network

### Phase 3 — Orchestrator & generate endpoint (done)
- The full turn above, with the time budget, cancellation, the 1-repair limit and the 2-tool-call limit
- Status rules: `generated` / `blocked` / `unavailable`; errors from tools passed on with secrets removed
- Checks for mismatched IDs, unknown tools, prompt injection in customer data and 256 KiB body limit
- **Done when:** the contract tests pass: no Gemini call on preblocked plans, at most 2 tool calls, at most 1 repair, stable schema, budget exhaustion → 504
